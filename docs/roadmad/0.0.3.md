## 0.0.3 — Real Type Model, Honest Diagnostics, and First-Class Aggregates

The first two milestones grew the *surface* of the language (statements,
expressions, operators). 0.0.3 turns inward to make that surface **sound**:
enforce the static-typing guarantee the project is named for, give values a real
runtime representation, and replace the compile-time tricks that currently make
objects, arrays, and `this` collapse on anything but the narrowest happy path.

Everything below the first two P0 themes depends on them — float, classes, and
unions all need a trustworthy type and a real value model first. Items are
ordered by dependency, not by size.

> Status note: several 0.0.2 items shipped as runtime stubs (`typeof`, `in`,
> `delete`, `instanceof`, `new`, regexp literals, `this`) or as broken
> placeholders (`for-in` iterates a hardcoded key list). 0.0.3 either replaces
> them with real implementations or moves them to `docs/NOT_COVERED.md`. See the
> "Make 0.0.2 honest" pre-work below.

> **Checkbox legend:** `[x]` done · `[~]` partially landed (notes inline) ·
> `[ ]` not started.

### Pre-work — consolidate before extending

Small, already-landed or near-term fixes that put 0.0.3 on an honest baseline:

- [x] **Assert the C compile succeeds in the test harness** (`tests/helper.ts`
  now checks `cc`'s exit code, surfaces its stderr, and deletes stale binaries
  so a miscompile can't pass on a previous artifact).
- [x] **Grouping operator `( )`** — implement `ParenthesizedExpression`
  (was marked done in 0.0.1 but threw `not support`).
- [x] **`>>>=`** — emit a valid `(unsigned int)` cast instead of the invalid C
  token `>>>`.
- [x] **`getAllVars` operator check** — `kind === EqualsToken` instead of the
  bitwise `kind & EqualsToken` that fed wrong data into closure analysis.
- [x] **Make the docs honest** — `0.0.2.md`, `README.md`, and `NOT_COVERED.md`
  now mark the stubbed/partial features accurately (`typeof`, `in`, `delete`,
  `instanceof`, `new`, regexp, `this`, `for-in`). The misleading `forInST1`
  fixture (asserted `count 3` over an empty `{}`) was removed — for-in has no
  honest passing fixture until it is really implemented (Theme 2).
- [x] **Cover implemented-but-untested features** — added fixtures for the
  `void` operator, comma operator, and binary bitwise (`& | ^`) / logical
  (`&& ||`) operators, with outputs verified against `node`.

### Theme 1 — Foundation: diagnostics gate + type lowering (P0)

The unblocker. Nothing else in this milestone is sound without it.

- [x] **Diagnostics gate** — `transpile()` now serves a controlled minimal
  ambient lib (`src/rtsLib.ts`) alongside the user source and runs
  `ts.getPreEmitDiagnostics`; any diagnostic aborts with the formatted
  TypeScript error(s). `let n: number = true`, `5 + true`, and runtime type
  changes are rejected. (Limitation: calling a non-function is not caught under
  the minimal `noLib` lib — assignability/type-change violations are.)
- [x] **Constrain / reject `any`** — explicit `any` annotations are now rejected
  with a located error (`assertNoExplicitAny` in `program.ts`). Benign implicit
  inference (e.g. the empty-array literal `[]` → `any[]`) is left alone.
- [x] **Type-lowering pass** — a single dedicated mapper `loweredType(ts.Type):
  string` (in `src/emit/helper.ts`) is now the one place that turns a TS type
  into a C type. Every former ad-hoc `checker.getTypeAtLocation` lowering site —
  function params/returns, closure fields, variable decls, for / for-of loop
  vars, and program-level globals — routes through it (`tsType2CStrict` is kept
  as a back-compat alias). It still throws a clear `not support` for aggregates
  (objects, arrays, function values as types — owned by Theme 2).
- [x] **Negative-test category** — `tests/unittest/diagnostics.spec.ts` asserts
  ill-typed programs are rejected and well-typed ones accepted;
  `transpileError.spec.ts` asserts unsupported type lowering throws `not support`.

### Theme 2 — First-class value & aggregate model (P0)

Replace the compile-time flattening with real runtime values. Direct
prerequisite for classes.

- [x] **Objects as structs** — each object *shape* lowers to a named C struct
  typedef (`Obj_<sorted-fields>`, identical shapes share one name) emitted in the
  preamble; object literals become C99 compound literals `((Obj_a){ .a = 7 })`,
  and object-typed values are passed to / returned from functions, declared, and
  reassigned **by value**. Replaces the global `obj_<pos>_<end>_<prop>`
  flattening and the `objectBindings` map. `tsType2C` now lowers object types to
  their struct name (so they work as param/return/variable types). _Still TODO:
  arrays-of-objects (non-primitive array element storage)._
- [x] **General property access & writes** — `expr.prop` resolves to a real C
  struct field access `(expr).prop` on **any** object-typed expression
  (identifiers, parameters, call results, compound literals) via the checker, not
  just identifiers bound to a literal; `obj.x = v` lowers to `(obj).x = v`.
  Fixtures: `objectParam`, `objectPropertyWrite`, `objectReturnProperty`.
- [x] **Length-carrying arrays** — the element count is stored in slot `[0]`
  (array literals no longer append a `0` sentinel; `for-of` reads the count from
  `[0]` and elements from index 1), so a real `0` element no longer truncates
  iteration. _Still TODO: non-`int` element types once the value model exists._
- [x] **Real `for-in`** — iterates the iterated object type's **actual** field
  names (static, declaration order) as `char*` keys, replacing the hardcoded
  `{"length","toString","valueOf"}` list. Fixture: `forInObjectKeys`
  (`{a:1,b:2}` → `a` / `b`).
- [~] **Tagged scalars** — `null` is distinguished at the C *type* level:
  `tsType2C` lowers `null`/`undefined`-typed values to `void *` (never int/
  double), so they no longer collapse to the numeric/boolean type. The `null`
  literal itself still emits `0` (the C null-pointer constant, valid in both the
  `void *` slot and the `int` fallback that a widened `let x = null` receives).
  _Still TODO: distinguishing `number`/`boolean`/`null` values at runtime (a
  boxed/tagged value) — the full prerequisite for honest `typeof` and unions._

### Theme 3 — Number model: float / double (P1)

The smallest semantically meaningful expansion; exercises the new machinery on a
tractable scope. (Resolves the `number = int` limitation in `NOT_COVERED.md`.)

- [x] **`number` → floating type** — `number` now lowers to C `double`. Numeric
  integer literals carry a `.0` so `5 / 2` is `2.5` (not int-divided to `2`);
  `%` lowers to `fmod`, `%=` to `x = fmod(x, y)`; bitwise/shift cast through
  `int` (`((int)(a) OP (int)(b))`), `>>>` casts double→int→unsigned, `~` casts
  to `int`; `switch`/`case` cast to `int`. Number arrays are `double[]` with the
  slot-`[0]` length scheme (`(int)ptr[0]` on read); globals / loop vars / for-of
  vars declare their lowered C type. `math.h` is in the preamble. Verified:
  `1.5`, `5/2=2.5`, `5.5%2=1.5`, and the existing bitwise/shift/compound
  fixtures keep their exact outputs (2/7/4, 8/25/15/12/5/2, 2/1073741822, 2/8).
- [x] **Type-directed output** — `console.log` picks its printer from the
  operand's static/lowered type: numbers via a new `rts_print_number` (integers
  clean, e.g. `3`/`1073741822`, floats via `%g`); strings via
  `printf("%s\n", …)` with no surrounding quotes; booleans/comparisons via
  `… ? "true" : "false"`; string concat as a single printf using `%s`/`%g`. The
  hardcoded `%d` and the fragile quote-stripping are gone.
- [x] **Real `typeof`** — `typeof` is resolved at compile time from the
  operand's static type and emitted as a C string literal of the JS type name
  (`number`/`string`/`boolean`/`function`/`object`/`undefined`; `typeof null`
  is `"object"`). Drops the runtime `rts_typeof` dependency for these.

### Theme 4 — Closures hardening (P1)

De-risk the area patched in PR #3 before methods build on it.

- [~] **Structured capture pass** — the regex body-rewrite
  (`bodyString.replace(/^\{\n/, …)`) is gone: the closure-context setup is now
  prepended as a REAL first statement via a new `EmitterOption.prependStatements`
  hook consumed by `blockEmitter` (which strips it so it does not leak into
  nested blocks). _Still uses the `allVars`-minus-`boundVars` heuristic. Capture
  across MORE than one level (a→b→c) is NOT sound yet: the innermost function's
  context-param type is named after its immediate parent, but the single shared
  context struct is named after the outermost owner, so a 3-level program
  miscompiles (struct-name mismatch). Single-level capture is solid; the
  multi-level fix is deferred._
- [~] **Unify function-decl and function-expression paths** —
  `functionDeclare.ts` exposes a shared `emitFunctionLike(node, option, emitName)`
  core; `functionExpressionEmitter` now delegates to it, so a function expression
  runs the same capture machinery as a function declaration. The function-pointer
  declarator now carries the leading `struct …_closure*` context param and the
  call through the holding variable passes the active `closure_ctx`. _A nested
  function-expression body is currently emitted TWICE (a statement-stream
  double-emit specific to the value form), so `const f = function(){…}` that is
  then called runs twice — no honest fixture yet. Non-capturing/top-level function
  expressions are unaffected (`functionExpression.rts` still passes)._
- [~] **Escaping closures** — an outer function that returns one of its nested
  functions now heap-allocates its closure context
  (`malloc(sizeof(struct …))`) instead of stack-allocating `&__closure_data`, so
  a returned function pointer + its context would survive the parent frame.
  _Not yet end-to-end: a function VALUE as a return type still hits the
  `not support` type-lowering gate (no function-pointer return lowering / indirect
  returned-call plumbing), so a full returned-counter program does not transpile
  yet. The heap-allocation half is in place; the value-model half is deferred.
  No `free` (program-lifetime leak)._
- [x] Fixture for sibling closures with overlapping names (`siblingClosures`).
  _Multi-level fixture deferred until the multi-level struct-naming fix lands._

### Theme 5 — Classes, methods, and full `this` (P2)

The headline `NOT_COVERED.md` item and the natural endpoint of the subset.
Sits on top of Themes 1, 2, and 4.

> **Status: DEFERRED / not landed.** An implementation attempt exists in
> `src/emit/statement/classDeclaration.ts` (struct + receiver functions + a
> `__type_id` tag) and instance method calls / `instanceof` work, but the core
> lowering is broken — member access uses the wrong receiver, the constructor
> body leaks into `main()`, and `new` drops its arguments. Rather than emit
> invalid C, the `ClassDeclaration` emitter is **unwired**, so `class` throws
> `not support`. The items below remain unchecked until the lowering is rewritten.

- [ ] **Class lowering** — class → struct (fields) + standalone functions for
  methods that take an explicit receiver pointer.
- [ ] **Constructors / `new`** — `new` actually allocates and initializes
  (replace the `rts_new` dummy).
- [ ] **Real `this`** — bind `this` to the method's receiver parameter instead
  of the permanently-`NULL` global `this_context`.
- [ ] **Real `instanceof`** — check against class identity (replace the
  `rts_instanceof -> 1` stub).
- [ ] Keep prototype-chain semantics in `NOT_COVERED.md`; ship only a flat class
  model (own fields/methods) for 0.0.3.

### Theme 6 — Modules: import / export (P2)

Orthogonal to single-file semantics; can run in parallel with classes. The
codebase already flags this (`getFunctionName` TODO in `helper.ts`).

- [x] **Stable name mangling** across files and a link step — `transpileProgram(files)`
  builds all modules + the ambient lib into one ts.Program and links them into a
  single C translation unit; `getFunctionName` folds the defining file into the
  mangle so same-offset functions in different modules don't collide.
- [x] **`export` / `import`** of functions and consts across RTS files, gated by
  the diagnostics pass so cross-file type errors are caught. Imports/exports are
  no-ops in the linked unit; an imported call is resolved through its alias to the
  real declaration (same mangled name); a cross-file type error (`add("hi", 3)`)
  is rejected. Covered by `tests/unittest/modules.spec.ts`.
