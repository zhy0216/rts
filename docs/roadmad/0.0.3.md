## 0.0.3 — Real Type Model, Honest Diagnostics, and First-Class Aggregates

The first two milestones grew the *surface* of the language (statements,
expressions, operators). 0.0.3 turns inward to make that surface **sound**:
enforce the static-typing guarantee the project is named for, give values a real
runtime representation, and replace the compile-time tricks that currently make
objects, arrays, and `this` collapse on anything but the narrowest happy path.

Everything below the first two P0 themes depends on them — float, classes, and
unions all need a trustworthy type and a real value model first. Items are
ordered by dependency, not by size.

> Status note: several 0.0.2 items shipped as runtime stubs (`typeof`, `in`,
> `delete`, `instanceof`, `new`, regexp literals, `this`) or as broken
> placeholders (`for-in` iterates a hardcoded key list). 0.0.3 either replaces
> them with real implementations or moves them to `docs/NOT_COVERED.md`. See the
> "Make 0.0.2 honest" pre-work below.

> **Checkbox legend:** `[x]` done · `[~]` partially landed (notes inline) ·
> `[ ]` not started.

### Pre-work — consolidate before extending

Small, already-landed or near-term fixes that put 0.0.3 on an honest baseline:

- [x] **Assert the C compile succeeds in the test harness** (`tests/helper.ts`
  now checks `cc`'s exit code, surfaces its stderr, and deletes stale binaries
  so a miscompile can't pass on a previous artifact).
- [x] **Grouping operator `( )`** — implement `ParenthesizedExpression`
  (was marked done in 0.0.1 but threw `not support`).
- [x] **`>>>=`** — emit a valid `(unsigned int)` cast instead of the invalid C
  token `>>>`.
- [x] **`getAllVars` operator check** — `kind === EqualsToken` instead of the
  bitwise `kind & EqualsToken` that fed wrong data into closure analysis.
- [x] **Make the docs honest** — `0.0.2.md`, `README.md`, and `NOT_COVERED.md`
  now mark the stubbed/partial features accurately (`typeof`, `in`, `delete`,
  `instanceof`, `new`, regexp, `this`, `for-in`). The misleading `forInST1`
  fixture (asserted `count 3` over an empty `{}`) was removed — for-in has no
  honest passing fixture until it is really implemented (Theme 2).
- [x] **Cover implemented-but-untested features** — added fixtures for the
  `void` operator, comma operator, and binary bitwise (`& | ^`) / logical
  (`&& ||`) operators, with outputs verified against `node`.

### Theme 1 — Foundation: diagnostics gate + type lowering (P0)

The unblocker. Nothing else in this milestone is sound without it.

- [x] **Diagnostics gate** — `transpile()` now serves a controlled minimal
  ambient lib (`src/rtsLib.ts`) alongside the user source and runs
  `ts.getPreEmitDiagnostics`; any diagnostic aborts with the formatted
  TypeScript error(s). `let n: number = true`, `5 + true`, and runtime type
  changes are rejected. (Limitation: calling a non-function is not caught under
  the minimal `noLib` lib — assignability/type-change violations are.)
- [x] **Constrain / reject `any`** — explicit `any` annotations are now rejected
  with a located error (`assertNoExplicitAny` in `program.ts`). Benign implicit
  inference (e.g. the empty-array literal `[]` → `any[]`) is left alone.
- [~] **Type-lowering pass** — `tsType2CStrict` now throws a clear `not support`
  error (instead of leaking the token `undefined`) at function param/return and
  closure-field sites. Still TODO: a dedicated `LoweredType -> C type` mapper
  replacing the ad-hoc per-site `checker.getTypeAtLocation` calls, and concrete
  C types for aggregates (see Theme 2).
- [x] **Negative-test category** — `tests/unittest/diagnostics.spec.ts` asserts
  ill-typed programs are rejected and well-typed ones accepted;
  `transpileError.spec.ts` asserts unsupported type lowering throws `not support`.

### Theme 2 — First-class value & aggregate model (P0)

Replace the compile-time flattening with real runtime values. Direct
prerequisite for classes.

- [ ] **Objects as structs** — lower each object type to a real C struct (or a
  tagged/boxed value) so objects can be passed to and returned from functions,
  reassigned, and stored in arrays. Replaces the global `obj_<pos>_<end>_<prop>`
  flattening.
- [ ] **General property access & writes** — resolve `expr.prop` on any
  object-typed expression (params, call results, array elements), not just
  identifiers directly bound to a literal; support `obj.x = v`.
- [x] **Length-carrying arrays** — the element count is stored in slot `[0]`
  (array literals no longer append a `0` sentinel; `for-of` reads the count from
  `[0]` and elements from index 1), so a real `0` element no longer truncates
  iteration. _Still TODO: non-`int` element types once the value model exists._
- [ ] **Real `for-in`** — iterate the actual object's keys (or formally drop
  `for-in` to `NOT_COVERED.md`).
- [ ] **Tagged scalars** — give `number` / `boolean` / `null` distinguishable
  runtime representations (today all collapse to `int`; `null == false == 0`).
  Prerequisite for honest `typeof` and for unions.

### Theme 3 — Number model: float / double (P1)

The smallest semantically meaningful expansion; exercises the new machinery on a
tractable scope. (Resolves the `number = int` limitation in `NOT_COVERED.md`.)

- [ ] **`number` → floating type** — stop unconditionally collapsing
  `number -> int`; support a `double` (or int/double split) so float literals
  like `1.5` are not truncated.
- [~] **Type-directed output** — `console.log` now prints all comparison
  operators (`<= >= == !=` included) as `true`/`false`. _Still TODO: replace the
  hardcoded `%d` and the fragile quote-stripping string-concat special case with
  format selection (`%d` / `%f` / `%s`) driven by the lowered type, and stop
  wrapping string literals in quotes._
- [ ] **Real `typeof`** — return the operand's lowered type instead of the
  constant `"number"`.

### Theme 4 — Closures hardening (P1)

De-risk the area patched in PR #3 before methods build on it.

- [ ] **Structured capture pass** — replace the regex body-rewriting closure
  injection and the `getAllVars`-minus-`boundVars` heuristic; handle locals
  declared in nested blocks/loops and capture across more than one level.
- [ ] **Unify function-decl and function-expression paths** so
  `const f = function () {}` captures identically to a function declaration.
- [ ] **Escaping closures** — a returned closure currently fails to compile and,
  even if it didn't, its context is stack-allocated in the parent frame
  (use-after-return). Give escaping closures a heap-allocated context whose
  pointer travels with the returned value.
- [ ] Fixtures for multi-level and sibling closures with overlapping names.

### Theme 5 — Classes, methods, and full `this` (P2)

The headline `NOT_COVERED.md` item and the natural endpoint of the subset.
Sits on top of Themes 1, 2, and 4.

- [ ] **Class lowering** — class → struct (fields) + standalone functions for
  methods that take an explicit receiver pointer.
- [ ] **Constructors / `new`** — `new` actually allocates and initializes
  (replace the `rts_new` dummy).
- [ ] **Real `this`** — bind `this` to the method's receiver parameter instead
  of the permanently-`NULL` global `this_context`.
- [ ] **Real `instanceof`** — check against class identity (replace the
  `rts_instanceof -> 1` stub).
- [ ] Keep prototype-chain semantics in `NOT_COVERED.md`; ship only a flat class
  model (own fields/methods) for 0.0.3.

### Theme 6 — Modules: import / export (P2)

Orthogonal to single-file semantics; can run in parallel with classes. The
codebase already flags this (`getFunctionName` TODO in `helper.ts`).

- [ ] **Stable name mangling** across files and a link step (concatenate or emit
  multiple translation units).
- [ ] **`export` / `import`** of functions and consts across RTS files, gated by
  the diagnostics pass so cross-file type errors are caught.
